## 2.5단계 — 1인칭 전장 (3D) ✅ (완료)

`fps.html` + `src/fps/`. **시뮬레이션은 손대지 않고 시점만 하나 더 붙였다** —
`Game`·`Enemy`·`Tower`·`WaveManager`는 2D가 쓰던 것 그대로이고, 3D 층은 상태를
읽어 three.js 장면으로 비추고 입력을 같은 명령 메서드로 돌려보낸다. 덕분에
밸런스 시뮬레이터가 검증한 수치가 두 시점에서 똑같이 성립한다.

- [x] 절차적 지형 — 격자를 한 장의 텍스처로 굽고, 바위·소나무·토성·성문만 메시로 세운다
- [x] 절차적 기물·적 모형 — **레벨이 병력 수로 보이고**, 실루엣 규칙(갑주·산개·기마)을 3D로 옮겼다
- [x] 걷는 적 — 관절에 매단 팔다리를 **이동 거리**에서 뽑은 박자로 흔든다 (감속이 발걸음에서 보인다)
- [x] 성벽 세 겹 — 체성·미석·여장에 치(雉)와 지대석. 인스턴스 다섯 벌로 끝낸다
- [x] 기물 장비와 발사 동작 — 등패·죽절·신기전·완구, 부품별 반동, 숨 쉬는 대기 자세
- [x] 1인칭 이동 — 눈높이 고정, 지형·기물·적과 실제로 부딪힌다
- [x] 시선 조준 배치 — 손이 닿는 거리(6칸) 안에서만. 걸어 다닐 이유를 만드는 제약이다
- [x] 미니맵 · 땅에 그린 사거리 원 — 1인칭에서 잃는 정보를 메운다
- [x] 2D와 진행도(해금·기록) 공유

남은 것: 소리, 야간 시야 보정 옵션, 성벽 위로 올라가는 계단(높이 축이 생기면
배치 판단이 한 겹 더 늘어난다).

## 3단계 — 코어 심화

**게임플레이**

- [ ] 액티브 스킬 2종 (쿨다운제) — 운석 낙하(광역 순수 데미지) / 시간 정지
      → 위기 상황의 역전 수단. 현재는 웨이브가 시작되면 플레이어가 할 일이 없다
- [ ] 타워 4레벨에서 2갈래 분기 (예: 궁수대 → 저격탑 / 연사탑)
      → Kingdom Rush의 티어 4 특화 구조. 빌드 다양성의 주 공급원
- [ ] 적 특수 능력 — 자가 치유, 사망 시 분열, 아군 보호막

**콘텐츠**

- [ ] 맵 추가 — 도중에 갈라졌다 합치는 분기 경로(현재는 여러 경로가 나란히 갈 뿐이다)
- [ ] 무한 모드 — 웨이브 자동 생성 + 난이도 스케일링. `WaveManager`만 교체하면 된다
- [ ] "키우기" 빌드 살리기 — 현재 6기 만렙 빌드는 S5 0% / S6 5%.
      **데이터 튜닝으로는 안 된다는 것이 측정으로 확인됐다** ([`BALANCE.md`](BALANCE.md) 14장):
      업그레이드 비용을 25% 깎아도 S5는 그대로 0%이고(병목이 골드가 아니다),
      사거리를 올리면 살아나지만 **몰빵 빌드도 같이 살아난다**(총통 몰빵 S6 0% → 100%).
      위의 4레벨 분기처럼 레벨업이 "더 세게"가 아니라 "덮는 방식이 달라진다"를 줘야 한다

## 4단계 — 확장

- [ ] 병영 유닛 (경로 차단 + 근접 교전). 이동·교전 AI가 필요해 코어 대비 규모가 크다.
      **타겟팅 우선순위를 진짜 선택지로 만드는 자리이기도 하다** ([`BALANCE.md`](BALANCE.md) 15장):
      지금은 "새면 진다"는 제약 때문에 「선두」 외의 값이 전부 손해인데, 선두를 맡아 주는
      차단 역할이 따로 있으면 나머지 기물이 효율을 볼 여유가 생긴다

- [ ] 메타 진행 — 웨이브 클리어 시 별 획득 → 영구 강화 트리

## 기술 부채 / 알려진 제약

| 항목 | 내용 | 영향 |
|---|---|---|
| 경로 웨이포인트 | 축에 평행한 구간만 지원 (`Path.occupiedTiles`가 던진다) | 대각선·곡선 경로 불가 |
| 다중 경로 | 여러 경로가 각자 독립적으로 정의된다 (합류는 좌표가 겹치도록 손으로 맞춤) | 진짜 분기(한 경로가 둘로 갈라짐)는 아직 불가 |
| 웨이브 데이터 | 목표 HP 곡선에서 생성해 명시값으로 박아 뒀다 | 곡선을 바꾸려면 손으로 다시 계산해야 한다. 생성 규칙은 BALANCE.md 4장에 기록 |
| 타겟 탐색 | 매 프레임 전체 적 순회 (O(타워 × 적)) | 적 200마리 이상에서 프레임 드랍 예상. 공간 분할 필요 |
| 지형 캐시 | 오프스크린 캔버스 1장, 레벨 변경 시 `invalidateTerrain()` 수동 호출 필요 | 멀티 레벨 도입 시 실수하기 쉬움 |
| UI | 2D는 캔버스 직접 그리기 (DOM 아님) | 접근성·텍스트 선택·다국어 줄바꿈에 불리. **3D 쪽 HUD는 DOM으로 지었다**(`src/fps/Hud.ts`) — 2D도 옮길 때의 참고가 된다 |
| 3D 번들 | three.js가 gzip 138KB. `fps.html`만 내려받는다 | 2D 페이지는 영향 없음. 진입점을 가른 이유가 이것이다 |
| 테스트 | 단위 테스트는 없고, 헤드리스 시뮬레이터가 사실상의 회귀 테스트 역할을 한다 | **CI로 묶었다** — `npm run balance`가 설계 의도를 검사하고 어긋나면 실패한다 ([`BALANCE.md`](BALANCE.md) 13장). 단위 테스트가 없는 상태 자체는 그대로다 |
| 시뮬레이터 AI | 결정적이라 임계값 근처에서 비단조적 결과가 나온다 | 클리어율을 절대값으로 신뢰하지 말고 전략 간 상대 비교로 읽을 것 |
