## Services와 무엇이 다른가

둘 다 「만들어 본 것」이지만 **성공의 기준이 다르다.**

- **Games** — 재미가 기준이다. 밸런스·난이도 곡선·화면이 읽히는가로 판가름 난다.
- **Services** — 쓸모가 기준이다. 정확한가·빠른가·안 죽는가로 판가름 난다.

기준이 다르면 검증도 다르다. 게임은 "이 수치가 재미를 깨뜨리는가"를 물어야 하는데
그건 눈으로 잘 안 보여서, 조선 방어전은 **시뮬레이터와 회귀 게이트**를 갖고 있다
(`npm run balance`). 서비스라면 같은 자리에 단위 테스트와 모니터링이 온다.

애매하면 이렇게 묻는다: *이걸 평가할 때 "재밌나?"를 먼저 묻는가, "되나?"를 먼저
묻는가.* 앞이면 여기, 뒤면 [`Services/`](../Services/).

## 프로젝트를 추가할 때

저장소 루트 [`README.md`](../README.md)의 「배포」 절을 따른다 — `deploy.yml`의
「배포 트리 조립」 단계에 한 줄, `site/index.html`에 카드 하나, 그리고 위 표와
루트 표에 한 줄씩.
