## 2단계 — 코어 심화

**게임플레이**

- [ ] 액티브 스킬 2종 (쿨다운제) — 운석 낙하(광역 순수 데미지) / 시간 정지
      → 위기 상황의 역전 수단. 현재는 웨이브가 시작되면 플레이어가 할 일이 없다
- [ ] 타워 4레벨에서 2갈래 분기 (예: 궁수탑 → 저격탑 / 연사탑)
      → Kingdom Rush의 티어 4 특화 구조. 빌드 다양성의 주 공급원
- [ ] 적 특수 능력 — 자가 치유, 사망 시 분열, 아군 보호막

**콘텐츠**

- [ ] 맵 2~3개 추가 (분기 경로 / 다중 출발점)
- [ ] 무한 모드 — 웨이브 자동 생성 + 난이도 스케일링. `WaveManager`만 교체하면 된다
- [ ] "키우기" 빌드 살리기 — 현재 6기 만렙 빌드는 0% 클리어. 업그레이드 비용 인하 또는
      레벨당 사거리 증가폭 확대 검토 ([`BALANCE.md`](BALANCE.md) 6장 Q5)

## 기술 부채 / 알려진 제약

| 항목 | 내용 | 영향 |
|---|---|---|
| 경로 웨이포인트 | 축에 평행한 구간만 지원 (`Path.occupiedTiles`가 던진다) | 대각선·곡선 경로 불가 |
| 타겟 탐색 | 매 프레임 전체 적 순회 (O(타워 × 적)) | 적 200마리 이상에서 프레임 드랍 예상. 공간 분할 필요 |
| 지형 캐시 | 오프스크린 캔버스 1장, 레벨 변경 시 `invalidateTerrain()` 수동 호출 필요 | 멀티 레벨 도입 시 실수하기 쉬움 |
| UI | 캔버스 직접 그리기 (DOM 아님) | 접근성·텍스트 선택·다국어 줄바꿈에 불리. UI가 더 복잡해지면 DOM 오버레이 검토 |
| 테스트 | 단위 테스트는 없고, 헤드리스 시뮬레이터가 사실상의 회귀 테스트 역할을 한다 | 밸런스 데이터를 고치면 `npm run sim`을 돌려야 한다. CI로 묶어 클리어율이 목표 구간을 벗어나면 실패시키는 것이 다음 후보 |
| 시뮬레이터 AI | 결정적이라 임계값 근처에서 비단조적 결과가 나온다 | 클리어율을 절대값으로 신뢰하지 말고 전략 간 상대 비교로 읽을 것 |
