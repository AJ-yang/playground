# 밸런스 검증 보고서

`npm run sim`으로 실제 게임 코드를 렌더링 없이 돌려 얻은 결과다.
브라우저와 **완전히 같은 `Game` 클래스를 같은 1/60초 고정 타임스텝**으로 굴리므로,
여기 나온 수치는 추정이 아니라 실제 플레이의 수치다.

---

## 1. 검증 방법

### 시뮬레이터 구성

```
src/sim/
├─ coverage.ts    건설 가능 타일을 "경로를 얼마나 오래 사정권에 두는가"로 순위 매김
├─ strategies.ts  빌드 방침만 다르게 둔 대조군 AI들
├─ headless.ts    한 판을 끝까지 돌려 결과 레코드를 뽑는다
└─ run.ts         스테이지 × 전략 × 시드를 돌리고 집계·감사 표를 출력
```

핵심은 **대조 실험**이다. 배치 알고리즘·판단 주기·업그레이드 규칙을 전부 동일하게 고정하고
**"어떤 타워를 짓는가" 하나만** 바꾼다. 그래야 클리어율 차이를 빌드 탓으로 돌릴 수 있다.

**스테이지마다 그 시점에 해금된 타워만 준다.** 이게 진행 설계의 검증 그 자체다 —
S4를 거마작 없이 못 깬다면 S3의 보상이 제 역할을 한다는 뜻이고, 거마작이 있으나 없으나
같다면 그 해금은 허울이다.

- 시드는 `0x1000 + i × 7919`로 고정 — 같은 명령이면 항상 같은 결과가 나온다
- 전략은 결정적(난수 없음) — 결과 차이는 오직 스폰 지터 시드에서만 온다
- 판단 주기 0.5초, 준비 단계에서 살 수 있는 것을 다 살 때까지 골드를 소진
- 해금되지 않은 타워를 고르면 쓸 수 있는 것 중 가장 싼 것으로 대체한다

### 명령

```bash
npm run sim                      # 전체 스테이지 × 전체 전략 × 20판
npm run sim -- --stage fork      # 특정 스테이지만
npm run sim -- --runs 50         # 시드 수 지정
npm run sim -- --only balanced,adaptive-frost1
npm run sim -- --markdown        # 이 문서에 붙일 표 형태로 출력
npm run sim -- --audit           # 스테이지별 압박·수입 곡선 (시뮬레이션 없이 데이터만)
npm run sim -- --income 1.3      # 수입 전역 배율 스윕 (튜닝용, 데이터는 건드리지 않음)
npm run sim -- --hp 0.8          # 적 HP 전역 배율 스윕 (튜닝용)
```

`--income`과 `--hp`는 밸런스의 양쪽 축이다. 데이터를 손으로 여러 번 고쳐가며 재는 대신
배율로 스윕해 목표 구간을 찾은 뒤, 확정된 값만 데이터 파일에 반영한다.

### 시뮬레이터의 한계 (결과를 읽을 때 감안할 것)

- **AI는 최적 플레이가 아니다.** 배치는 커버리지 순위 상위부터 채우고, 웨이브 중 대응이 없고,
  타워를 팔지 않는다. 사람이 더 잘할 수도, 더 못할 수도 있다.
- **AI가 결정적이라 임계값 근처에서 비단조적 결과가 나온다.** 클리어율은 절대값보다
  전략 간 상대 비교로 읽어야 한다.
- **타겟팅 우선순위는 전부 기본값(선두)** — 이 축은 여전히 검증하지 않았다.

## 2. 검증이 잡아낸 버그

**패배 판정이 조용히 취소되던 문제** (`src/game/Game.ts`)

"거마작 몰빵" 전략이 **생명 0으로 20웨이브를 클리어**하는 결과가 나왔다. 있을 수 없는 조합이라
추적해 보니, 웨이브의 마지막 적이 유출되며 생명이 0이 된 직후 같은 프레임의
`checkWaveCompletion()`이 `phase`를 `'prep'`으로 덮어쓰고 있었다. 승리·패배를 종착 상태로
못 박는 `setPhase()` 가드로 수정했다.

**중독 피해가 타워 기여도에 잡히지 않던 문제**

비격진천뢰의 딜 점유율이 4%로 나왔는데, 지속 피해가 `Enemy.update`에서 적용되어 쏜 타워에
귀속되지 않고 있었다. 지표만의 문제였지만 그대로 뒀다면 "비격진천뢰는 쓸모없다"는 잘못된 결론으로
이어졌을 것이다. 귀속을 고치니 10%로 올라갔다.

## 3. 스테이지 도입 이전 (단일 20웨이브 시절)

첫 검증에서 **11개 전략 중 10개가 100% 클리어, 대부분 생명 20/20 무손실**이었다.
원인은 경제였다 — 이론상 수입 11,462G인데 타워 14기 만렙 비용은 4,500G, 2.5배 초과 공급.
골드가 남아도니 상성 페널티가 타워 개수로 상쇄됐다.

수입 −39%, 궁수대 정체성 복원(L3 데미지 36 → 24), 적 방어 상향, 거마작 서포터화를 적용해
몰빵 0% / 조합 87~100%까지 잡았다. 자세한 경위는 이 문서의 이전 판(git 히스토리) 참고.

## 4. 스테이지 도입 후 다시 무너진 것

스테이지를 나누면서 **골드가 스테이지마다 0부터 다시 시작**하게 됐는데, 웨이브는 여전히
"20웨이브 내내 누적한다"는 전제로 쓰여 있었다. 결과는 S2~S5가 전부 초반 전멸이었다.

여기서 나온 가장 중요한 발견:

> **경로가 갈라지면 난이도가 급격히 올라간다.**
> 타워 커버리지가 경로 수만큼 나뉘기 때문이다. 같은 압박 수치로 맞췄을 때
> 1갈래 맵(S1·S4)은 여유롭게 클리어되고 2갈래(S3)·3갈래(S5)는 초반에 무너졌다.
> 다중 경로 맵은 압박을 **절반 이하로** 낮춰야 같은 체감 난이도가 된다.

그래서 웨이브를 스테이지마다 **목표 HP 곡선**에서 다시 생성했다. 각 스테이지는
`base × ramp^(웨이브-1)`의 HP 예산을 갖고, 마지막 웨이브만 ×1.6. 예산을 적 구성 비율로
나눠 개체 수를 정한다. 확정된 값은 `src/data/stages.ts`에 명시적으로 박아 뒀다.

| 스테이지 | 경로 | 웨이브 | base | ramp | 총 적 HP |
|---|---|---|---|---|---|
| S1 왜구의 노략 | 1 | 8 | 520 | 1.38 | 약 12,000 |
| S2 삼포왜란 | 1 | 10 | 620 | 1.29 | 약 25,000 |
| S3 임진왜란 | **2** | 12 | 430 | 1.26 | 약 30,000 |
| S4 정묘호란 | 1 | 14 | 960 | 1.235 | 약 55,000 |
| S5 병자호란 | **3** | 20 | 430 | 1.11 | 약 55,000 |

**스폰 시간 상한도 넣었다.** 초기 생성에서 S1 마지막 웨이브에 적이 632마리 나오는 일이
있었는데, 개체 HP가 60인 잡몹으로 압박을 만들려니 수가 폭발한 것이다. 그룹 하나의 스폰이
35초를 넘지 않도록 간격을 조여, 개체 수가 늘수록 촘촘하게 나오게 했다.

## 5. 검증 결과 (각 스테이지 × 13전략 × 20판)

### S1 왜구의 노략 — 8웨이브 · 궁수대만

전 전략 **100% 클리어, 생명 20/20**. 쓸 수 있는 타워가 궁수대뿐이라 모든 전략이 같은 판을
돌린다(해금되지 않은 선택은 궁수대로 대체된다). **의도된 튜토리얼**이며, 이 스테이지는
"경로를 덮는다"는 기본기만 가르친다. 긴장감이 필요하면 여기가 아니라 S2부터다.

### S2 삼포왜란 — 10웨이브 · 궁수대·총통

| 전략 | 클리어율 | 평균 클리어 웨이브 | 남은 생명 |
|---|---|---|---|
| 궁수대 몰빵 | **0%** | 7.0 ± 0.2 | 0.0 |
| 총통 몰빵 | 100% | 10.0 | 18.6 |
| 균형 (궁수대·총통) | 100% | 10.0 | 13.2 |

갑병(갑주 12)가 주역이라 **총통 없이는 W7에서 막힌다.** 직전 스테이지의 보상이

## 6. 열린 질문

- **비격진천뢰가 정말 필요한가?** S5는 독 없이도 100% 클리어된다(생명 4.3 vs 6.5).
  S4의 거마작처럼 "없으면 못 깬다" 수준은 아니다. 최종 스테이지에 양면 저항 적의 비중을
  더 올리거나, 독을 더 강하게 하거나, 아니면 "있으면 편한 선택지"로 두는 것을 인정하거나 —
  셋 중 하나를 정해야 한다. **현재는 해금 보상 중 유일하게 필수성이 검증되지 않았다.**
- **화차의 기마 페널티**는 여전히 미검증. 징 몰빵이 기마 등장 전에 화력 부족으로 죽는다.
  "징 + 궁수대" 같은 지상 편중 조합 대조군이 필요하다.
- **S1이 완전히 무손실**이다. 튜토리얼로는 맞지만 한 번도 새지 않으면 생명 시스템 자체를
  배우지 못한다. 마지막 웨이브만 살짝 아프게 할지 검토.
- **타겟팅 우선순위** 축 미검증.
- **"키우기" 빌드**는 S2 25% / S3 60% / S4 0% / S5 35%로 여전히 열세다. 경로가 긴 맵일수록
  커버리지가 레벨보다 중요하다.

## 7. 재현

```bash
npm run sim -- --runs 20            # 5장 표
npm run sim -- --runs 20 --markdown # 그대로 이 문서에 붙일 수 있는 형태
npm run sim -- --audit              # 4장 압박·수입 곡선
```

밸런스 데이터를 고친 뒤에는 반드시 이 명령을 다시 돌리고 5장 표를 갱신할 것.
