# 밸런스 검증 보고서

`npm run sim`으로 실제 게임 코드를 렌더링 없이 돌려 얻은 결과다.
브라우저와 **완전히 같은 `Game` 클래스를 같은 1/60초 고정 타임스텝**으로 굴리므로,
여기 나온 수치는 추정이 아니라 실제 플레이의 수치다.

**현재 판**: 스테이지 6 · 기물 7종 · 적 20종 · 대조군 전략 17종.
6스테이지 × 17전략 × 20판 = **2,040판, 약 85초**.

---

## 1. 검증 방법

### 시뮬레이터 구성

```
src/sim/
├─ coverage.ts    건설 가능 타일을 "경로를 얼마나 오래 사정권에 두는가"로 순위 매김
├─ strategies.ts  빌드 방침만 다르게 둔 대조군 AI들
├─ headless.ts    한 판을 끝까지 돌려 결과 레코드를 뽑는다
└─ run.ts         스테이지 × 전략 × 시드를 돌리고 집계·감사 표를 출력
```

핵심은 **대조 실험**이다. 배치 알고리즘·판단 주기·업그레이드 규칙을 전부 동일하게 고정하고
**"어떤 타워를 짓는가" 하나만** 바꾼다. 그래야 클리어율 차이를 빌드 탓으로 돌릴 수 있다.

**스테이지마다 그 시점에 해금된 타워만 준다.** 이게 진행 설계의 검증 그 자체다 —
S2를 총통 없이 못 깬다면 S1의 보상이 제 역할을 한다는 뜻이고, 있으나 없으나 같다면
그 해금은 허울이다.

- 시드는 `0x1000 + i × 7919`로 고정 — 같은 명령이면 항상 같은 결과가 나온다
- 전략은 결정적(난수 없음) — 결과 차이는 오직 스폰 지터 시드에서만 온다
- 판단 주기 0.5초, 준비 단계에서 살 수 있는 것을 다 살 때까지 골드를 소진
- 해금되지 않은 타워를 고르면 쓸 수 있는 것 중 가장 싼 것으로 대체한다

### 명령

```bash
npm run sim                      # 전체 스테이지 × 전체 전략 × 20판
npm run sim -- --stage fork      # 특정 스테이지만
npm run sim -- --runs 50         # 시드 수 지정
npm run sim -- --only balanced,adaptive-frost1
npm run sim -- --markdown        # 이 문서에 붙일 표 형태로 출력
npm run sim -- --audit           # 스테이지별 압박·수입 곡선 (시뮬레이션 없이 데이터만)
npm run sim -- --income 1.3      # 수입 전역 배율 스윕 (튜닝용, 데이터는 건드리지 않음)
npm run sim -- --hp 0.8          # 적 HP 전역 배율 스윕 (튜닝용)
```

`--income`과 `--hp`는 밸런스의 양쪽 축이다. 데이터를 손으로 여러 번 고쳐가며 재는 대신
배율로 스윕해 목표 구간을 찾은 뒤, 확정된 값만 데이터 파일에 반영한다.

### 시뮬레이터의 한계 (결과를 읽을 때 감안할 것)

- **AI는 최적 플레이가 아니다.** 배치는 커버리지 순위 상위부터 채우고, 웨이브 중 대응이 없고,
  타워를 팔지 않고, **자리를 다시 잡지 않는다**. 사람이 더 잘할 수도, 더 못할 수도 있다.
- **AI가 결정적이라 임계값 근처에서 비단조적 결과가 나온다.** 클리어율은 절대값보다
  전략 간 상대 비교로 읽어야 한다. 5장의 `균형 + 거마작` S3 항목이 그 실례다.
- **타겟팅 우선순위는 전부 기본값(선두)** — 이 축은 여전히 검증하지 않았다.

## 2. 검증이 잡아낸 버그

**패배 판정이 조용히 취소되던 문제** (`src/game/Game.ts`)

"거마작 몰빵" 전략이 **생명 0으로 20웨이브를 클리어**하는 결과가 나왔다. 있을 수 없는 조합이라
추적해 보니, 웨이브의 마지막 적이 유출되며 생명이 0이 된 직후 같은 프레임의
`checkWaveCompletion()`이 `phase`를 `'prep'`으로 덮어쓰고 있었다. 승리·패배를 종착 상태로
못 박는 `setPhase()` 가드로 수정했다.

**중독 피해가 타워 기여도에 잡히지 않던 문제**

비격진천뢰의 딜 점유율이 4%로 나왔는데, 지속 피해가 `Enemy.update`에서 적용되어 쏜 타워에
귀속되지 않고 있었다. 지표만의 문제였지만 그대로 뒀다면 "비격진천뢰는 쓸모없다"는 잘못된 결론으로
이어졌을 것이다. 귀속을 고치니 10%로 올라갔다.

## 3. 지나온 두 번의 붕괴 (요약)

**(1) 스테이지 도입 이전** — 첫 검증에서 11개 전략 중 10개가 100% 클리어, 대부분 무손실이었다.
원인은 경제였다: 이론상 수입 11,462G인데 타워 14기 만렙 비용은 4,500G. 골드가 남아도니
상성 페널티가 타워 개수로 상쇄됐다. 수입 −39%, 궁수대 정체성 복원(L3 36 → 24),
적 방어 상향으로 몰빵 0% / 조합 87~100%까지 잡았다.

**(2) 스테이지 도입 직후** — 골드가 스테이지마다 0부터 시작하는데 웨이브는 "20웨이브 내내
누적한다"는 전제로 쓰여 있어 S2~S5가 전부 초반 전멸했다. 여기서 나온 가장 중요한 발견:

> **경로가 갈라지면 난이도가 급격히 올라간다.**
> 타워 커버리지가 경로 수만큼 나뉘기 때문이다. 다중 경로 맵은 압박을 **절반 이하로**
> 낮춰야 같은 체감 난이도가 된다.

그래서 웨이브를 스테이지마다 **목표 HP 곡선**(`base × ramp^(웨이브-1)`, 마지막만 ×1.6)에서
다시 생성하고, 확정된 값을 `src/data/stages.ts`에 명시적으로 박아 뒀다.
자세한 경위는 이 문서의 이전 판(git 히스토리) 참고.

## 6. 거마작에 대한 별도 기록 — 「언제 짓는가」에 답을 붙인 과정

이번 판의 가장 큰 밸런스 변경이라 따로 남긴다.

**증상.** 6스테이지 체제로 넓힌 직후, 거마작을 지을수록 결과가 나빠졌다.
S3에서 `적응형 · 거마작` 0기 100% / 1기 65% / 2기 0% / 3기 0%로 **완벽하게 단조 감소**했다.
거마작을 처음 손에 쥐는 스테이지가 하필 거마작을 지으면 지는 스테이지였던 셈이다.

**틀린 진단 두 개.**
- *경제 문제인가?* `--income` 스윕으로 확인했다. ×1.45까지 올려도 0기(생명 15.0)가
  3기(6.8)를 계속 이겼고, ×1.3부터는 궁수대 몰빵이 92% 클리어해 "몰빵은 막힌다"는
  성질이 먼저 깨졌다. **경제는 원인이 아니다.**
- *배치 문제인가?* `pickSpot(preferEarly)`가 상위 40% 커버리지 안에서 가장 앞쪽 자리를
  고르는 것을 확인했다. 합리적인 규칙이라 여기도 아니다.

**진짜 원인.** 거마작에는 "언제 짓는가"의 답이 없었다. 보병에게도 기병에게도 똑같이
−55% 걸리는 균일 감속은, 딜이 0인 대가로는 어느 웨이브에서도 충분히 좋지 않았다.
AI가 거마작을 지으면 그냥 **화력 한 기를 버리는 것**이었다.

**고친 방식.** 감속을 기마에 몰아줬다. `TowerLevelDef.cavalrySlow`를 추가해
`enemy.def.flying`일 때만 `slowAmount + cavalrySlow`(상한 0.95)를 적용한다.

| 레벨 | 보병 감속 | 기마 감속 |
|---|---|---|
| 1 | −52% | **−78%** |
| 2 | −64% | **−90%** |
| 3 | −74% | **−95%** |

이건 튜닝이기 전에 **고증**이다. 거마작(拒馬柵)은 이름 그대로 *말을 막는* 물건 —
통나무에 창을 꽂아 기병의 돌격선을 끊는 장애물이지 보병용 방어물이 아니었다.
보병에게나 기병에게나 똑같이 듣던 이전 수치가 오히려 어색했다.

같은 논리로 시뮬레이터 AI의 판단 기준도 바꿨다. 전에는 `웨이브 ≥ 5`면 조건 없이 한 기를
지었는데, 이제 **다가오는 웨이브의 기마 HP 비중이 20%를 넘을 때만** 짓는다.

**결과.** S3의 단조 감소가 사라졌다.

| S3 전략 | 변경 전 | 변경 후 |
|---|---|---|
| 적응형 · 거마작 1기 | 65% | **95%** |
| 적응형 · 거마작 2기 | 0% | **100%** |
| 적응형 · 거마작 3기 | 0% | **100%** |
| 균형 · 옛 다섯 종만 | 0% | **90%** |
| 균형 · 일곱 종 전부 | 85% | **100%** |
| 키우기 우선 | 0% | **100%** |

**남은 것.** `균형 + 거마작`만 S3에서 0%로 남았다(5장 참고). 거마작을 더 많이 짓는 빌드가
100%인 이상 거마작의 문제가 아니라고 판단해 그대로 뒀다.

## 7. 열린 질문

- **`적응형 · 거마작 0기`가 여전히 여러 스테이지에서 1위다.** S4 15.8 vs 2기 15.8(동률),
  S5 14.3 vs 5.7, S6 5.5 vs 1.2. 6장의 변경으로 "거마작을 지으면 진다"는 없어졌지만
  "안 지어도 된다"는 남아 있다. 다만 이 AI는 **타워를 팔지도 옮기지도 않아** 순수 DPS
  편향이 구조적으로 있다 — 사람 플레이로 교차 검증하기 전에는 결론을 못 낸다.
- **비격진천뢰가 정말 필요한가?** 최종 스테이지도 독 없이 100% 클리어된다.
  **해금 보상 중 필수성이 검증되지 않은 유일한 기물**로 남아 있다.
- **불랑기포도 아직 필수가 아니다.** S6에서만 열리는데 S6는 6종만으로도 클리어된다.
  최종 보상이 아니라 **S5 보상**이라는 점이 문제를 덮고 있다 — S6 마지막 웨이브들의
  기마 비중을 더 올리면 자리가 생길 것 같다.
- **화차의 기마 페널티**는 여전히 미검증. 화차 몰빵이 기마 등장 전에 화력 부족으로 죽는다.
- **S1이 사실상 무손실**이다. 튜토리얼로는 맞지만 한 번도 새지 않으면 생명 시스템 자체를
  배우지 못한다. 마지막 웨이브만 살짝 아프게 할지 검토.
- **타겟팅 우선순위** 축 미검증.
- **「키우기」 빌드**는 S5 0% / S6 0%로 후반에 무너진다. 경로가 길고 갈라질수록
  커버리지가 레벨보다 중요하다 — 이건 버그가 아니라 성립한 성질로 읽는다.
