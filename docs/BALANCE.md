# 밸런스 검증 보고서

`npm run sim`으로 실제 게임 코드를 렌더링 없이 돌려 얻은 결과다.
브라우저와 **완전히 같은 `Game` 클래스를 같은 1/60초 고정 타임스텝**으로 굴리므로,
여기 나온 수치는 추정이 아니라 실제 플레이의 수치다.

---

## 1. 검증 방법

### 시뮬레이터 구성

```
src/sim/
├─ coverage.ts    건설 가능 타일을 "경로를 얼마나 오래 사정권에 두는가"로 순위 매김
├─ strategies.ts  빌드 방침만 다르게 둔 대조군 AI들
├─ headless.ts    한 판을 끝까지 돌려 결과 레코드를 뽑는다
└─ run.ts         여러 전략 × 여러 시드를 돌리고 집계·감사 표를 출력
```

핵심은 **대조 실험**이다. 배치 알고리즘·판단 주기·업그레이드 규칙을 전부 동일하게 고정하고
**"어떤 타워를 짓는가" 하나만** 바꾼다. 그래야 클리어율 차이를 빌드 탓으로 돌릴 수 있다.

- 시드는 `0x1000 + i × 7919`로 고정 — 같은 명령이면 항상 같은 결과가 나온다
- 전략은 결정적(난수 없음) — 결과 차이는 오직 스폰 지터 시드에서만 온다
- 판단 주기 0.5초, 준비 단계에서 살 수 있는 것을 다 살 때까지 골드를 소진

### 명령

```bash
npm run sim                      # 전체 전략 × 30판
npm run sim -- --runs 50         # 시드 수 지정
npm run sim -- --only balanced,adaptive-frost1
npm run sim -- --markdown        # 이 문서에 붙일 표 형태로 출력
npm run sim -- --audit           # 웨이브별 압박·수입 곡선 (시뮬레이션 없이 데이터만)
npm run sim -- --income 1.3      # 수입 전역 배율 스윕 (튜닝용, 데이터는 건드리지 않음)
```

### 시뮬레이터의 한계 (결과를 읽을 때 감안할 것)

- **AI는 최적 플레이가 아니다.** 배치는 커버리지 순위 상위부터 채우고, 웨이브 중 대응이 없고,
  타워를 팔지 않는다. 사람이 더 잘할 수도, 더 못할 수도 있다.
- **AI가 결정적이라 임계값 근처에서 비단조적 결과가 나온다.** 수입 배율 ×1.2에서
  "적응형·얼음 1기"가 0%, ×1.25에서 94%로 튀는 구간이 있었다. 이건 밸런스가 불안정한 게
  아니라 AI가 특정 시점에 타워 하나를 못 사서 매번 같은 곳에서 무너지는 것이다.
- **타겟팅 우선순위는 전부 기본값(선두)** — 이 축은 검증하지 않았다.

## 2. 검증이 잡아낸 버그

**패배 판정이 조용히 취소되던 문제** (`src/game/Game.ts`)

"얼음탑 몰빵" 전략이 **생명 0으로 20웨이브를 클리어**하는 결과가 나왔다. 있을 수 없는 조합이라
추적해 보니, 웨이브의 마지막 적이 유출되며 생명이 0이 된 직후 같은 프레임의
`checkWaveCompletion()`이 `phase`를 `'prep'`으로 덮어쓰고 있었다. 그 뒤로는 생명 0인 채로
게임이 무한히 계속된다.

승리·패배를 종착 상태로 못 박는 `setPhase()` 가드로 수정했다. 렌더링 스모크 테스트로는
잡히지 않았을 버그다 — 수백 판을 돌려야 드러나는 종류다.

## 3. 검증 전: 밸런스가 무너져 있었다

첫 실행 결과 (수정 전, 30판씩):

| 전략 | 클리어율 | 남은 생명 |
|---|---|---|
| 궁수탑 몰빵 | **100%** | 20.0 |
| 마법탑 몰빵 | **100%** | 20.0 |
| 균형 (궁수·마법·대포) | 100% | 20.0 |
| 넓히기 우선 | 100% | 20.0 |

11개 전략 중 10개가 클리어했고 대부분 **생명을 하나도 잃지 않았다.**
GDD가 설계 의도로 내세운 "단일 빌드는 반드시 막힌다"가 전혀 성립하지 않았다.

### 원인: 경제가 2.5배 초과 공급

`--audit`이 지목한 숫자:

```
이론상 최대 수입   11,462G   (현상금 8,267 + 클리어 보상 2,935 + 시작 260)
타워 14기 만렙 비용 약 4,500G
```

GDD는 누적 획득을 "약 4,000G"로 추정했다. **실제는 11,202G — 2.8배 틀렸다.**
골드가 남아돌아 어떤 빌드든 14기를 전부 만렙으로 올렸고, 그러면 상성 페널티가
개수로 상쇄된다. 궁수탑(물리)이 장갑 18짜리 수정 감시자를 뚫는 이유가 이것이었다.

### 부수적으로 드러난 것

- **얼음탑이 최고 딜러였다.** 딜 점유율 58~63%. 광역 마법 데미지 18이 뭉친 적 10마리를
  한 번에 때리니 누적 딜이 단일 대상 타워를 압도했다. "딜 없는 서포터"라는 설계와 정반대.
- **궁수탑이 저데미지 타워가 아니었다.** L3 데미지 36은 마법탑 L1의 32보다 높다.
  "물리 고정 감소가 저데미지·고연사 타워를 죽인다"는 상성의 전제 자체가 성립하지 않았다.

수입 배율은 `--income`으로 1.15~1.8을 스윕해 **×1.25**를 고른 뒤 데이터에 확정했다.

## 6. GDD 9장 열린 질문에 대한 답

**Q1. 20웨이브 클리어가 실제로 가능한가?**
→ **가능하다.** 조합 빌드가 87~100% 클리어, 남은 생명 4~11 (시작 20).
생명을 절반 가까이 잃고 끝나므로 긴장감도 유지된다.

**Q2. 조기 소환 보너스 2G/초가 너무 후한가?**
→ **아니다.** 클리어 여부를 뒤집지 않는다(100% → 100%). 남은 생명만 6.9 → 11.0으로
올라간다. 즉 **여유가 있을 때 더 여유로워지는 선택지**이지, 필수 최적해가 아니다.
다만 방어선이 갖춰진 뒤엔 항상 부르는 게 이득이므로, 후반 웨이브의 준비 시간은
사실상 무의미해진다. 의도한 동작이면 그대로 두고, 아니라면 보너스를 웨이브 번호에
반비례시키는 것이 다음 후보다.

**Q3. 얼음탑이 실제로 픽되는가?**
→ **1기는 픽된다.** 얼음 0기(생명 6.0) < 1기(6.9). 하지만 2기 이상은 클리어율이
97% → 73%로 떨어진다. **서포터 1기가 최적, 과투자는 응징**이라는 의도한 형태가 나왔다.
수정 전에는 최고 딜러였고, 딜만 깎은 중간 단계에서는 순손해였다.

**Q4. 대포탑의 "공중 불가" 페널티가 광역 성능을 상쇄할 만큼 아픈가?**
→ **검증하지 못했다.** 대포 몰빵은 공중 유닛이 처음 나오는 W6까지 가지도 못하고
**W2에서 절대 화력 부족으로 죽는다**(130G · 연사 0.55). 즉 대포 단독이 막히는 이유는
공중 페널티가 아니라 초반 DPS 부족이다. 조합 안에서는 딜 점유율 9~34%로 제 몫을 한다.
공중 페널티 자체를 재려면 "대포 + 궁수" 같은 지상 편중 조합을 별도 대조군으로
돌려야 한다 — 다음 라운드 과제.

**Q5. 3레벨 업그레이드 비용 곡선이 신규 건설과 경쟁이 되는가?**
→ **아니다. 신규 건설이 확실히 우위다.** 6기를 만렙으로 키우는 빌드는 0% 클리어(W17.4에서 저지),
14~20기를 넓게 까는 빌드는 100%. 경로가 길어 **커버리지가 레벨보다 중요**하다.
이건 나쁜 밸런스라기보다 이 맵의 성질이다 — 경로가 짧거나 사거리 밖 사각이 많은 맵을
추가하면 반대 결론이 나올 수 있다. 다만 지금은 "키우기" 선택지가 사실상 죽어 있으므로,
업그레이드 비용을 낮추거나 레벨당 사거리 증가폭을 키우는 것이 후보다.

## 7. 남은 문제

- **대포탑·얼음탑 단독이 W2~3에서 죽어 상성 검증이 불가능하다.** 두 타워 모두
  단독 캐리를 상정하지 않은 설계이므로 치명적이진 않지만, 페널티가 실제로 아픈지를
  재려면 별도 조합 대조군이 필요하다.
- **모든 전략의 첫 유출이 W4로 동일하다.** 강철 병사(장갑 12)가 처음 나오는 시점인데,
  초반 골드로 마련한 화력으로는 감당이 빡빡하다는 뜻이다. 의도된 학습 지점인지
  단순히 너무 이른지는 사람 플레이테스트가 필요하다.
- **"키우기" 빌드가 죽어 있다** (Q5 참고).
- **타겟팅 우선순위 축을 전혀 검증하지 않았다.** 전부 기본값(선두)으로 돌렸다.

## 8. 재현

```bash
npm run sim -- --runs 30            # 5장 표
npm run sim -- --runs 30 --markdown # 그대로 이 문서에 붙일 수 있는 형태
npm run sim -- --audit              # 3장 경제 감사
```

밸런스 데이터를 고친 뒤에는 반드시 이 명령을 다시 돌리고 5장 표를 갱신할 것.
