# 게임 평가

`new-game` 루프의 4~6번만 떼어낸 것이다. 이미 있는 게임을 한 회차 더 돌려볼 때
쓴다.

`Games/CONTRIBUTING.md`의 「루프」와 「산출물의 자리」를 먼저 읽어라.

## 순서

### 1. 대상과 등급을 확인한다

`docs/GDD.md`에서 등급을 본다. GDD가 없으면 T1으로 본다.

- **T2** — `balance-analyst` + `playtester` 둘 다
- **T1** — `playtester`만

### 2. 평가 — 반드시 **병렬**

한 메시지에서 두 에이전트를 동시에 띄운다. 순차로 돌리면 뒤엣것이 앞엣것을
볼 수 있고 독립적인 두 관측이라는 전제가 깨진다.

`playtester`에게 주는 것은 **게임 제목과 조작 진입점뿐이다.** 설계 의도·밸런스
수치·이전 회차의 처방을 프롬프트에 흘리지 마라.

`balance-analyst`에게는 GDD를 주어도 된다 — 재미 가설이 게이트 규칙의
원재료다.

### 3. 사람에게 정리해 보여준다 ← 여기서 멈춘다

```
balance   판정: 통과 못 함 — S4 12%, 목표 구간(40~70%) 밖. 2회차 78%에서 뒤집힘
playtest  판정: 재플레이 안 함 — 3분 지점에서 왜 지는지 모르겠어서 껐다
          ← 「무엇이 뚫는지 안 보인다」는 1·2회차에서도 나왔다. 세 번째.
```

**세 번 반복된 지적을 반드시 짚어라.** 회차를 쌓는 이유가 그것이다.

숫자와 인상이 어긋나는 지점도 짚어라. "밸런스는 통과인데 재플레이 안 함"이면
문제는 난이도가 아니라 다른 데 있다는 뜻이고, 그게 이 회차의 가장 중요한
발견이다.

### 4. 처방은 사람과 합의한 뒤에

무엇이 문제인지 합의되면 `game-designer`를 불러 `docs/ROADMAP.md`에 처방을
append 하게 한다. **평가 결과를 곧바로 처방으로 옮기지 마라.**

구현까지 이어갈지는 사람에게 물어라.

## 한 세션에 한 게임

**게임 두 개를 한 세션에서 연달아 평가하지 마라.** 앞 게임의 판정과 숫자가
네가 써 주는 지시문에 묻어 들어가고, 그러면 두 번째 게임은 첫 번째 게임을
기준으로 평가받는다. 나눠서 돌려라.

## 규칙

- **판정 없는 회차는 실패로 친다.** 에이전트가 판정 한 줄 없이 돌아오면 다시
  시켜라.
- 평가 문서(`BALANCE.md` · `PLAYTEST.md`)는 덮어쓰지 말고 쌓게 해라.
- 평가만 하고 코드를 고치지 마라. 이 스킬의 산출물은 문서와 합의다.
