# 조선 방어전 (Joseon War Defense)

경로형 타워디펜스 게임. TypeScript + HTML5 Canvas, 게임 엔진 의존성 없음.

**왜구의 노략에서 병자호란까지, 여섯 번의 전쟁으로부터 성을 지킨다.** 스테이지가
한 시대씩 나아가고, 깰 때마다 그 시대의 새 무기가 열린다 —
활·칼 → 총통·화차 → 거마작 → 조총 → 별파진 → 기고. 해금 순서가 곧 조선 화기의 기술사다.

타워를 짓는 게 아니라 **병(兵)·기(器)·책(柵)을 배치한다.** 여덟 종이 세 갈래로
나뉘고, 이름과 발밑 처리와 배치 목록의 묶음이 전부 그 갈래를 따른다. 기본 셋은 훈련도감의 **삼수병(三手兵)**
그대로다 — 사수(射手, 활)·살수(殺手, 칼)·포수(砲手, 조총).

Kingdom Rush · Bloons TD 6 · Plants vs. Zombies의 검증된 구조를 참고해
**타워 조합과 배치 판단**이 승패를 가르도록 설계했다.

## 실행

```bash
npm install
npm run dev        # http://localhost:5173
```

```bash
npm run typecheck  # 타입 검사
npm run build      # dist/ 로 프로덕션 빌드
npm run preview    # 빌드 결과 확인
npm run sim        # 헤드리스 밸런스 검증 (렌더링 없이 수백 판을 돌린다)
npm run balance    # 밸런스 회귀 게이트 — 설계 의도가 깨지면 종료 코드 1
```

## 스테이지와 해금

스테이지 6개를 순서대로 깨며, 깰 때마다 그 시대의 기물이 열린다. **한 판에 한 종씩이라는
규칙은 두지 않았다** — 첫 판은 두 종을 한꺼번에 주고, 마지막 판은 아무것도 주지 않는다.
기준은 개수가 아니라 **열린 것이 다음 판에서 곧바로 쓰이는가**다.

| 스테이지 | 맵 | 경로 | 웨이브 | 클리어 보상 |
|---|---|---|---|---|
| 1 왜구의 노략 | 완만한 S자 | 1갈래 | 8 | **총통 · 화차** |
| 2 삼포왜란 1510 | 촘촘한 지그재그 | 1갈래 | 10 | **거마작** |
| 3 니탕개의 난 1583 | 두 출발점이 합류 | **2갈래** | 12 | **포수** |
| 4 임진왜란 1592 | 길게 되접히는 나선 | 1갈래 | 14 | **별파진** |
| 5 정묘호란 1627 | 두 갈래가 합류 | **2갈래** | 16 | **기고** |
| 6 병자호란 1636 | 세 방향 동시 압박 | **3갈래** | 20 | — (최종) |

첫 판은 **사수와 살수**를 함께 준다 — 멀리서 얇게 vs 붙어서 두껍게, 정반대 축
둘이라 첫 판부터 선택이 생긴다.

스테이지는 실제 사건 순서를 따른다 — 1510 삼포왜란 · 1592 임진왜란 · 1627 정묘호란 ·
1636 병자호란. 적이 세지는 이유(잡졸 → 갑주 → 대군 → 기병 → 팔기군)를 역사가 설명해 준다.

새로 열린 기물은 **다음 스테이지에서 곧바로 쓰이도록** 배치했다. S1의 보상인 총통 없이는
갑병이 주역인 S2를 넘길 수 없고(사수 몰빵 0% vs 총통 몰빵 100%), S2의 보상인 거마작은
기병 전쟁인 S3에서 곧바로 값을 한다. 진행도는 브라우저에 저장된다.

`다음 스테이지` / `다시 하기` / `스테이지 선택` 버튼이 나온다.

## 난이도

타이틀 화면에서 고른다. **바뀌는 것은 적의 체력뿐** — 웨이브 구성·적 종류·타워 수치는
전부 동일하다. 쉬움에서 배운 풀이가 어려움에서도 그대로 통해야 하기 때문이다.

| 난이도 | 적 체력 | 성격 |
|---|---|---|
| 쉬움 | 70% | 상성을 익히며 여유 있게 |
| 보통 | 100% | 설계된 기준 난이도 |
| 어려움 | 125% | 조기 소환으로 경제를 굴려야 버틴다 |

해금은 난이도와 무관하게 공유하고, 최고 기록만 난이도별로 따로 남는다.

## 보스

스테이지 중간과 끝에 보스가 나온다. 물량 웨이브는 커버리지로 풀지만 보스는
**집중 화력과 상성**으로 풀어야 해서 같은 스테이지 안에서 다른 질문을 던진다.

| 보스 | 정체성 |
|---|---|
| 왜구 두목 | 방어 없는 덩치 — 순수 화력 시험 |
| 철갑 장수 | 갑주 22 — 물리 무력화, 총통 강제 |
| 선봉 기병 | 기마 + 빠름 — 화차 조준 불가 |
| 여진 대추장 | 기마 + 산개 62% — 화차도 화약도 안 통한다 |
| 누차 | 갑주 10에 체력 3,600 — 상성이 아니라 화력 총량을 묻는다 |
| 날랜 왜장 | 화약 저항 78% — 물리 강제 |
| 팔기 중군 | 갑주 + 산개 양면 — 비격진천뢰의 순수 피해가 답 |
| 팔기 대장 | 최종 보스 |

## 게임 규칙 요약

- 생명 **20**, 시작 골드 **270~580G** (스테이지별), 웨이브 **8~20개** (스테이지별)
- 적이 마을에 도달하면 생명이 깎이고, 0이 되면 패배
- 데미지 계산 — 이 게임의 모든 상성이 여기서 나온다
  - 관통: `max(1, 공격력 − 갑주)` → 저데미지·고연사 기물이 크게 손해
  - 화약: `max(1, 공격력 × (1 − 산개))` → 고데미지 기물도 똑같이 손해
  - 순수: `공격력` → 아무것도 막지 못한다 (별파진의 쇳조각)
  - **백병**: `max(1, 공격력 × (1 − 산개) − 갑주)` → **둘 다** 걸린다 (살수의 칼)
- **기마 유닛은 화차가 조준하지 못한다** — 대신 **거마작의 감속이 기마에게만 훨씬 깊게** 걸린다
- 감속과 중독은 중첩되지 않는다 (각각 가장 강한 것 하나만 적용) — 서포터 타워 도배를 막는다
- **경로가 갈라지는 맵은 훨씬 어렵다** — 타워 커버리지가 경로 수만큼 나뉜다
- 판매 시 투자 골드의 **70%** 환급

## 타워

| 기물 | 갈래 | 가격 | 타입 | 기마 | 역할 |
|---|---|---|---|---|---|
| 사수 | 병 | 70G | 관통 | ○ | 골드 대비 DPS 1위. 갑주 앞에서 무력 |
| 살수 | 병 | 80G | **백병** | ○ | 값싼 근접 광역. **갑주와 산개 둘 다에 깎이는 유일한 기물** |
| 포수 | 병 | 125G | 관통 | ○ | 사거리 1위(3.9~4.3칸)에 산개를 무시. **갑주 18부터 사수를 앞선다** |
| 총통 | 기 | 110G | 화약 | ○ | 갑주 완전 무시. 느리고 비싸며 산개에 막힘 |
| 화차 | 기 | 130G | 관통·광역 | **✕** | 지상 물량 정리. 발사가 매우 느림 |
| 거마작 | 책 | 75G | 화약·단일 | ○ | 딜은 없고 한 번에 하나만 묶는 감속(−18~28%). **기마에게는 −38~62%** — 말을 막는 물건이다 |
| 별파진 | 병 | 100G | **순수** | ○ | 비격진천뢰의 중독 지속 피해(최대 28/s × 4초). 갑주도 산개도 통과한다 |
| 기고 | 병 | 90G | — | — | **딜 0.** 지휘 반경 안 아군의 공격속도 +18~35%. 주변에 기물이 없으면 아무것도 안 한다 |

**여덟 종이 저마다 다른 칸을 하나씩 차지하도록** 축을 어긋나게 뒀다 — 살수는
가장 싸고 가장 짧고 방어에 가장 약한 광역, 화차는 넓지만 보병 전용, 사수는 싸고
짧고 저뎀, 포수는 비싸고 길고 고뎀.

**겹치는 것은 지웠다.** 불랑기포가 있었는데 골드당 유효 DPS를 여덟 개 적 원형에
대해 재 보니 **전부에서 총통보다 낮으면서 135G 더 비쌌다** — 광역이라는 이점을
계산에 넣고도 그랬다. 완전한 하위호환이라 없앴다.

**곱셈 축은 두 방향이다** — 거마작은 적을 느리게, 기고는 아군을 빠르게. 서로를
대체하지 않는다. 다만 **배치 판단은 정반대가 아니라 같다** — 「거마작은 경로 앞쪽에」는
그럴듯했지만 측정으로 틀린 것이 밝혀진 규칙이다([`docs/BALANCE.md`](docs/BALANCE.md) 8장).
감속은 **적이 가장 오래 머무는 곳**에 걸어야 하고, 그건 다른 기물이 노리는 자리와 같다.

## 적 읽는 법

적은 조선의 전쟁을 소재로 한 벡터 아트로 그리지만, **외곽 형태**가 "어떤 타워로 잡아야 하는가"를
알려준다는 규칙은 그대로다. 색만으로 판단하게 두지 않기 위해서다.

| 형태 | 생김새 | 의미 | 대응 |
|---|---|---|---|
| 원 | 수건 동인 졸병 | 방어 없음 | 아무 타워나 |
| 쐐기 (진행 방향) | 달리는 척후 / 결사대 | 고속 | 거마작 감속 |
| 원 (방어 표식 없음) | 맨몸 졸병 물량 | 무방비 | **살수**가 가장 싸게 쓸어버린다 |
| 육각 | 찰갑 두른 갑병 / 철기 | 갑주 | **총통** |
| 세로 마름모 | 두건 쓴 별동대 | 산개 | **활·탄환**(사수·포수) |
| 방패 오각 | 방패 든 방패병 / 지붕 덮은 충차 | 양면 저항 탱커 | 조합 |
| 사다리꼴 | 사다리를 걸치는 운제 / 누차 | 방어 0, 체력만 크다 | 화력 총량 |
| 가시 다각 | 수자기 든 팔기 대장 | 보스 | 전부 |
| **말 + 흙먼지 + 떠 있음** | 경기병 · 궁기병 · 철기 | 기마 | 화차 조준 불가 · **거마작이 특효** |

밝은 테두리 = 갑주, 보라 점선 = 산개, 하늘색 링 = 감속, 연두 점선 = 중독.
우측 패널의 다음 웨이브 미리보기가 **같은 그림**을 그려주므로 범례로 쓸 수 있다.

## 그래픽

스프라이트 파일이 없다. 모든 그림은 `src/render/art.ts`에 손으로 쓴 SVG 패스
데이터이고 `Path2D`로 그린다 — 기물 8종·무기 7종·적 20종·성·적진·바위·소나무.
분류가 **발밑에서 드러난다** — 병은 발자국 흙자국만, 기는 낮은 거치 받침, 책은 바닥.
예전엔 일곱이 전부 같은 흙 기단 위에 서 있어서 무엇을 그리든 「방어탑」으로 읽혔다.
패스는 평평한 단색만 칠하고, **명암과 표면 결은 렌더러가 준다** — 위에서 내려오는 빛,
왼쪽 위 하이라이트와 오른쪽 아래 그늘, 미세한 잡음 세 겹을 그림 위에 얹고 결과를
캐시한다. 그림마다 명암을 손으로 넣으면 모양을 고칠 때마다 명암도 같이 고쳐야 한다.
덕분에 에셋 로딩이 없고, 해상도에 무관하게 선명하며, `@color` 토큰으로 데이터의
색이 그림에 그대로 입혀진다. 지형(잔디·흙길·자갈)은 맵 ID를 시드로 한 절차적
드로잉이라 같은 맵은 항상 같은 모양이 나온다.

자세한 규칙은 [`docs/GDD.md`](docs/GDD.md) 5장.

## 구조

```
src/
├─ core/    엔진 (루프 · 벡터 · 시드 난수) — 게임 규칙을 모른다
├─ data/    밸런스 데이터 (타워 · 적 · 웨이브 · 맵) — 여기가 수치의 단일 진실 공급원
├─ game/    시뮬레이션 (Game · Grid · Path · Tower · Enemy · WaveManager) — 렌더링을 모른다
├─ render/  캔버스 그리기 (Renderer · art · shapes · palette) — 상태를 읽기만 한다
├─ ui/      HUD · 타이틀 · 스테이지 선택 · 레이아웃 · 입력 히트 테스트
└─ sim/     헤드리스 밸런스 검증 — Game만 쓰고 DOM을 모른다
```

밸런스를 조정하려면 `src/data/` 아래 파일만 고치면 된다.
고친 뒤에는 `npm run sim -- --runs 30`으로 재검증하고 [`docs/BALANCE.md`](docs/BALANCE.md) 5장 표를 갱신할 것.

- [`docs/GDD.md`](docs/GDD.md) — 설계 의도와 참고 게임 분석
- [`docs/BALANCE.md`](docs/BALANCE.md) — 밸런스 검증 방법·결과·근거
- [`docs/ROADMAP.md`](docs/ROADMAP.md) — 다음 작업 계획

## 밸런스 검증

`npm run sim`은 브라우저와 **같은 `Game` 클래스를 같은 고정 타임스텝**으로 렌더링 없이 돌린다.
빌드 방침만 다른 대조군 AI 20종 × 20판 × 6스테이지(2,400판)를 약 100초에 끝낸다.

```bash
npm run sim -- --stage fork        # 특정 스테이지만
npm run sim -- --runs 50           # 시드 수 지정
npm run sim -- --only balanced     # 특정 전략만
npm run sim -- --audit             # 스테이지별 압박·수입 곡선
npm run sim -- --income 1.3        # 수입 배율 스윕 (튜닝용)
npm run sim -- --hp 0.8            # 적 HP 배율 스윕 (튜닝용)
npm run balance                    # 회귀 게이트 (CI가 이걸 돌린다)
npm run sim -- --priority strongest # 타겟팅 우선순위 축 재검증
```

스테이지마다 **그 시점에 해금된 타워만** 주고 돌린다 — 진행 설계의 검증 그 자체다.

현재 검증 결과: 한 기물만 도배하는 빌드는 **S3 이후 전 스테이지에서 0~5%**
(S2의 총통 100%는 그 판의 교훈 자체다 — "갑주에는 화약"). 조합 빌드는 스테이지마다
최소 하나 이상이 100%. 자세한 표는 [`docs/BALANCE.md`](docs/BALANCE.md) 5장.
